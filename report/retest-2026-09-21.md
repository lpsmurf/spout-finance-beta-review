## Findings

| Sev | Finding |
|-----|---------|
| 🟠 | **No HSTS on beta.spout.finance.** Main site has `strict-transport-security: max-age=86400`; beta has none. First-visit plaintext MITM window on a wallet-signing surface. Add `max-age=63072000; includeSubDomains` like the CSP. |
| 🟠 | **The beta gate is UI-only.** `redeem_beta_code(email, code)` validates the pair server-side (dummy → `false`), but **no API route checks it**: `/api/orders/buy|sell|cancel`, `/api/market-data/*`, `/api/wallet/balances`, `/api/kyc/onboard` all answer without any redeemed code or session. The real access control is on-chain KYC identity + tx signature — fine for devnet, but the "passcode gate" protects only the page, not the backend. If they intend code-gating for load/abuse control, enforce it server-side. |
| 🟠 | **`redeem_beta_code` is unthrottled.** 4 rapid probes → 4× 200, no rate limit. email+passcode pairs are brute-forceable; Supabase doesn't rate-limit RPCs by default. Add attempt-limiting inside the function (or an edge rule). |
| 🟠 | **`/api/kyc/onboard` reachable unauthenticated** — takes only `{walletAddress}`; currently 500s (Persona env not wired or crashed). When working: creates Persona inquiries for *arbitrary* wallets → cost abuse + junk KYC records. Should require the Privy token like `/api/kyc/session` does. |
| 🔵 | **`access_count` RPC is public** — returns live beta-usage count (215 at test time). Trivial info disclosure; intentional if it's the "spots taken" counter. |
| 🔵 | **`/api/wallet/balances?userAddress=<any>`** public — returns balances for arbitrary addresses. On-chain data anyway; low impact. |
| 🔵 | **`/api/orders/buy` preflight leaks per-wallet state for arbitrary addresses** (SOL sufficiency, KYC identity existence, USDC ATA) — mild enumeration channel on devnet. Server-side preflight itself is good design (returned structured blockers: `insufficient-sol`, `kyc-no-identity`, `no-usdc-ata`). |
| 🔵 | Dead info: Next.js error page on 404s (version/tech disclosure); `x-nextjs-*` headers fingerprintable. |

## Verified clean

- **`/api/orders/submit` simulates before relay** — garbage input → `"Simulation failed: failed to deserialize VersionedTransaction"`. Signature is the real boundary. ✓
- **Supabase RLS/grants:** PostgREST root closed to anon; every plausible table (`profiles/orders/positions/kyc_*/beta_codes/wallets/…`) → 404/401 for anon. The earlier private note's open question ("confirm RLS on KYC/user tables") is now **verified directly: nothing readable via anon key.**
- **Auth config:** email provider only, `mailer_autoconfirm: false` (real email verification), `disable_signup: false`, no anon users.
- **No `.env`/`.git`/security.txt exposure** (404s; add `security.txt` for the bounty optics).
- CSP `frame-ancestors 'none'` + XFO DENY = clickjacking dead on both layers.

## Executed transaction test (signed, devnet — 2026-09-21)

Method: local signer page (localhost:8765) fetched a fresh unsigned tx from `/api/orders/buy` (GLD, $2), handed it to `window.phantom.solana.signTransaction`, relayed the signed blob to `/api/orders/submit`. Phantom signed; three submissions attempted.

**Result: all submissions reverted.** Server: `400 Simulation failed — custom program error: 0x177d` in `SPoRXgsB4gWZmWPwyndoRWQrmZXKUc7o7oPMdkkGRcG` instruction 2.

Independent devnet `simulateTransaction` (sigVerify:false) confirms root cause:

```
Instruction: PlaceBuyOrder
DEVNET: KYC verification bypassed (mock)
AnchorError thrown in programs/spoutOrdersV2/src/helper/oracle.rs:47.
Error Code: OraclePriceStale. Error Number: 6013. Error Message: Oracle price is stale.
```

**Findings from the signed test:**
- 🔴 **Buy is bricked too — not just borrow.** Every user-facing on-chain action routes through the oracle; keeper is >52h stale. A KYC-verified, funded beta user cannot complete ANY transaction (buy → stale oracle; deposit → needs tokens that can't be bought; preferences → needs vault; repay/withdraw → need vault). Total outage of the core product loop.
- 🟠 **Preflight gives false confidence.** `/api/orders/buy` preflight returned `blockers: []` for the same tx that reverts `OraclePriceStale` on simulation — buy preflight does NOT check oracle freshness while vault borrow preflight does. User signs a tx that cannot succeed → wasted signature + cryptic failure. Inconsistent preflight coverage.
- 🔵 Anchor error leaks internal source path `programs/spoutOrdersV2/src/helper/oracle.rs:47` (normal for Anchor; noted for completeness).
- 🔵 `DEVNET: KYC verification bypassed (mock)` — on-chain KYC check is a mock on devnet; identity-gating claims can't be validated from devnet behavior.
- ✅ Server-side simulation gate works: `/api/orders/submit` simulates before relaying and refuses bad txs — correct defense, though the error reaches the user raw.
- ✅ Phantom signing flow worked end-to-end through their wallet adapter's interface (signTransaction with custom title/description params).

**Auto-buyback:** preferences UI reveals an `autoBuyback` vault flag ("Lets the vault repurchase your collateral automatically after a liquidation") — the on-chain Auto-Roll equivalent, per-vault user setting. Cannot be set without an existing vault position (`initialize_vault must run before preferences`).
